Joomla 5.4.11 Known Issues and Compatibility Notes
===================================================

## Web Services API access requires `core.api`

Joomla 5.4.11 introduces a dedicated `core.api` permission for non-public Web Services endpoints. The default `ApiDispatcher` checks this permission before dispatching a request. API login (`core.login.api`) does not grant access to every component endpoint, and `core.manage` continues to control administrator component access.

Review the permissions for API user groups. Grant `core.api` for the components they need, as well as only the operation permissions required, such as `core.create`, `core.edit`, and `core.delete`. Depending on the endpoint, additional record-level checks also apply. Requests that do not pass authorization can return HTTP `403 Forbidden`.

Third-party extensions with custom API dispatchers should extend `Joomla\CMS\Dispatcher\ApiDispatcher` and preserve its access check. Joomla 5.4.11 also treats a route as public only when the `public` option is the Boolean `true`; previously used values such as `1` may now require authentication and authorization. Contact the extension developer if an integration is affected, and only make routes public when unauthenticated access is intended.

See [Removed and Backward Incompatibility](../removed-backward-incompatibility.md#web-services-use-coreapi-in-joomla-5411) for migration examples and details.
